Any holder of a tiny remote-domain USDC balance can drain 100% of an xReserve's holdings of any supported token by submitting a withdraw attestation request with useCircleForwarding: false and a spec.hookData whose embedded forwardingCalldata carries an inflated amount. The on-chain xReserve contract (0x8888888199b2Df864bf678259607d6D5EBb4e3Ce on Ethereum) performs no validation of forwardingCalldata against the attested transferSpec.value, and the documented public API at POST /v1/withdraw accepts user-signed BurnIntents whose hookData is structurally outside any feasible server-side amount check. All three forwarding paths (CCTP V1, CCTP V2, xReserve self-forwarding) drain in PoC tests against deployed mainnet bytecode. Realized financial impact today is small (~8.66 USDC currently in the reserve), but the bug is in the contract pattern that will be reused as xReserve scales.
